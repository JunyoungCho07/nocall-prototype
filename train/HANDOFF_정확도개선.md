# 작업 지시서 — 웹캠 데이터로 인식 정확도 개선 (fine-tune)

## 배경 (왜 하는가)
현재 모델은 Roboflow의 깔끔한 제품 사진으로 학습돼 **검증 mAP는 0.97**이지만,
실제 웹캠에서는 인식이 약하다. 원인은 **도메인 차이**:
- 학습된 제품이 특정 품목뿐 (콜라=캔만, 물=라벨 없는 빈 페트병만, 컵라면=신라면/진라면만)
- 학습 사진은 제품이 화면을 꽉 채운 클로즈업, 배경도 클래스마다 제각각
→ 실제 사용할 **제품·카메라·조명으로 직접 찍어 이어 학습(fine-tune)** 하면 해결된다.

## 목표
실제 데모에 쓸 제품 5종을 웹캠으로 촬영·라벨링해 학습 세트에 추가하고,
기존 모델을 fine-tune 하여 `models/nocall.pt`를 갱신한다.

## 사전 준비
- 이 저장소를 clone 하고 의존성 설치: `uv sync`
- **`train/nocall.yaml`의 `path:`를 본인 PC의 `train/data` 절대경로로 수정** (현재 작성자 PC 경로로 되어 있음)
- GPU(NVIDIA) 권장. 없으면 CPU로도 되지만 느림.
- 데모에 실제로 쓸 제품 5종 실물 준비:
  콜라 / 물 / 스낵봉지 / 시리얼 / 컵라면 (실제 데모에 등장할 '바로 그 제품'으로)
- **중요**: 서버(run.py)가 켜져 있으면 카메라를 점유하므로 끄고 시작할 것.

## 절차 (순서대로)

### 1단계 — 촬영
```
uv run python train/capture.py
```
- 영상 창에서 숫자 `0~4`로 클래스 선택 → `SPACE`로 촬영 (`a`=자동 연속, `q`=종료)
- **클래스당 30~50장 이상.** 각도·거리·회전·조명을 다양하게.
- 손에 들거나 카트에 넣는 실제 동작 그대로도 찍을 것.
- 저장: `train/data/webcam/images/<class>/`

### 2단계 — 라벨링
```
uv run python train/label_tool.py
```
- 이미지마다 제품을 마우스로 드래그 → `ENTER` (여러 개면 반복) → `ESC`로 다음
- 클래스는 폴더별로 자동 지정되므로 박스만 그리면 됨
- 중단했다 재실행해도 이어서 진행됨 (이미 라벨한 건 건너뜀)
- 저장: `train/data/webcam/labels/<class>/`

### 3단계 — 학습 세트에 합치기
```
uv run python train/add_webcam.py
```
- 웹캠 데이터를 기존 train/val에 85:15로 추가 (`webcam_` prefix)

### 4단계 — 이어 학습(fine-tune)
```
uv run python train/finetune.py
```
- 기존 `models/nocall.pt`에서 40 epoch 미세조정, 완료 시 자동으로 `models/nocall.pt` 갱신
- 결과 지표는 `runs/train/nocall_ft/` 에 저장됨

### 5단계 — 확인
```
uv run python run.py
```
- 브라우저 `http://localhost:8000` 접속, 실제 제품으로 인식 확인
- 박스에 표시되는 `클래스명 + 신뢰도(%)`로 판단:
  - 이름 맞고 80%+ → 성공
  - 여전히 약하면 → 해당 클래스 사진을 더 찍어 1~4단계 반복

## 합격 기준
- 5종 제품을 웹캠 앞에서 다양한 각도로 들었을 때 **이름이 정확히, 70% 이상**으로 표시
- 스캔라인(화면 중앙)을 위→아래로 통과시키면 장바구니에 정상 추가

## 팁 / 주의
- 잘 안 되는 클래스가 있으면 그 클래스만 더 촬영(1단계)하고 2~4단계 반복하면 됨
- 신뢰도가 전반적으로 낮으면 `app/camera.py`의 `conf` 값을 조정 (기본 0.30)
- 촬영 다양성이 정확도를 좌우함. 같은 구도만 많이 찍지 말 것.
- 카메라 인덱스가 0이 아니면 `capture.py`/`camera.py`의 `VideoCapture(0)`을 1,2로 변경
